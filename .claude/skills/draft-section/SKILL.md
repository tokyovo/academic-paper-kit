# Draft a section

## First, ask what the section must do

Each section has one job. Confirm which you are writing:

- **Introduction** — the problem, why it matters, what this paper does, and the
  contribution list. The contribution list is the human's; draft it only as a
  proposal and say so.

- **Method** — enough detail to reimplement. Notation defined once, used
  consistently.

- **Experiments** — datasets, baselines, metrics, hardware, seeds. A reader
  must be able to repeat it.

- **Results** — what the numbers show. Every number comes from
  `\input{tables/...}`, generated by `analysis/make_tables.py`.

- **Discussion** — what the results do not show. Limitations go here, honestly.

- **Conclusion** — no new claims.

## Rules while drafting

- One sentence per line in the `.tex` file.

- Never type a number. If a number is needed and no result file has it, say
  which run is missing.

- Cite only existing keys. Otherwise `\todo{CITE: ...}`.

- Match the evidence. One dataset does not support a general claim. Use
  "on example-v1" rather than "in general".

- Do not touch math mode, `\label`, `\ref`, `\cite` keys, or `siunitx` values
  when you are only polishing prose.

- Avoid the register that reads as machine-written: no "it is worth noting",
  no "delve into", no "in today's rapidly evolving landscape", no em-dash
  asides, no "not merely X but Y". Plain declarative sentences.

## After drafting

1. Add every new claim to `notes/claim_ledger.md`.

2. Run `make paper`, `make scrub`, `make check-refs`.

3. Append to `ai_use_log.md`: date, tool, model version, the section, the task.

4. Report to the user: what you wrote, which claims need their approval, and
   any `\todo` left open.

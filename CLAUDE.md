# Rules for writing this paper

You are a co-author, not the author. The human owns the hypothesis, the
contribution claims, the abstract and the conclusions. You own the drafting,
the LaTeX, the code and the checking.

These rules are not style advice. Breaking any of them is how papers get
desk-rejected or how authors get banned from arXiv.

## 1. Citations

- **Never invent a citation.** Cite only keys that already exist in
  `paper/refs.bib`.

- If you need a source that is not there, write
  `\todo{CITE: <what is needed>}` and stop. Do not guess a title, author,
  year or DOI.

- **Never cite from memory.** Every new entry in `refs.bib` must come from a
  real lookup: a DOI or arXiv import, a Zotero export, or `make find-refs`.
  Models invent references 14% to 95% of the time when recalling them, and
  they verify their own citations correctly only about 38% of the time.

- Every cited claim must be traceable to a passage in the source. When you
  draft from a source in `sources/`, put the page or quote in a LaTeX comment
  next to the sentence.

- Run `make check-refs` after any change to `refs.bib`. It must pass before
  you report work as done.

## 2. Numbers

- Every number in the text comes from `experiments/results/*.json` through
  `analysis/make_tables.py`. Never type a number by hand into a `.tex` file.

- Never draw a data plot from a description. Figures are generated by
  `analysis/make_figures.py` from real result files. A plot written from
  high-level instructions is a fabricated plot.

- Record the seed, the environment and the git commit hash with every result
  file.

## 3. Claims

- Before asserting a claim, add it to `notes/claim_ledger.md` with the file
  that proves it and the section where it appears.

- No "novel", "groundbreaking" or "state of the art" without a cited
  comparison in the same sentence.

- Hedge to match the evidence. One experiment on one dataset does not
  support a general statement.

## 4. LaTeX

- Do not edit inside math mode, inside `\label`, `\ref` or `\cite` keys, or
  inside `siunitx` values when you are polishing prose.

- After each edit run `make paper`. Report any error; do not work around a
  compile failure by deleting content.

- Keep one sentence per line in `.tex` files. It keeps diffs readable.

## 5. Disclosure

- Append to `ai_use_log.md` after any substantive help: date, tool, model
  version, the task, and the prompt if it shaped the content.

- Copy-editing and grammar fixes do not need a log entry at most venues, but
  logging them costs nothing.

## 6. Before the human submits

Run `make check`. It must pass clean. It runs:

- `make check-refs` — every reference verified against Crossref, OpenAlex and
  arXiv.

- `make scrub` — no leftover AI text, placeholders or unresolved `\todo`.

- `make paper` — the PDF compiles.

Then tell the human what `docs/venues.md` requires for their venue.

## What you must not do

- Do not write the abstract or the contribution list without the human
  approving the claims first.

- Do not add a reference you have not verified.

- Do not remove a `\todo{CITE}` marker by filling in a plausible source.

- Do not upload a manuscript you are reviewing for a venue into any model.
  Most venues forbid it.

## Working on the repo itself

No dependencies: the tools use the Python standard library only.
`matplotlib` is optional (figures). `latexmk` is needed only for `make paper`.

### Commands

- `make help` lists every target.
- `make test` runs the checkers on deliberately bad fixtures.
  Both tools must exit non-zero. CI asserts this with `!`.
- Run one checker alone:
  - `python3 tools/check_refs.py tools/tests/sample.bib --no-cache`
    (expect 2 ok, 2 NOT FOUND, 1 MISMATCH, exit 1)
  - `python3 tools/scrub.py tools/tests/dirty --strict` (expect 7 blocking)
- `check_refs.py` needs the network.
  It exits 1 when a lookup fails, so an offline run fails.
  The cache `.cache/refs.json` keeps only `ok` and `manual` results.
  `make check` uses `--no-cache`.

### How the parts connect

    experiments/results/*.json ──> analysis/make_tables.py  ──> paper/tables/*.tex
                               └─> analysis/make_figures.py ──> paper/figures/
    make find-refs (tools/find_refs.py) ──> paper/refs.bib ──> make check-refs
    paper/**/*.tex ──> make scrub (every \cite key must be in refs.bib)
    notes/claim_ledger.md ──> make ledger (evidence paths must exist)

- `paper/tables/` and `paper/figures/` are generated and git-ignored.
  Run `make tables figures` before `make paper`.
- A result file holds `run_id` (same as the file name), `commit` (a commit in
  this repo), `seed`, `dataset`, `environment{}` and `metrics{}`.
  `make check-results` enforces this.
- `make tables` also writes `paper/tables/results_macros.tex`: one macro per
  metric (`\resLiarTextTestAccuracy`). Write numbers in the text with these.
  `scrub` blocks a hand-typed decimal or percentage unless the line has a
  `\cite`.
- `find_refs.py` imports `get`, `clean_doi`, `normalize_title` and
  `arxiv_id_from_doi` from `check_refs.py`. After a change to one, test both.
- `scrub.py` skips any line that contains `scrub:ignore` and every macro
  definition. The `\todo` macro in `paper/main.tex` depends on this.
- The gates differ:
  - `make check` runs tables, figures, check-refs (no cache), check-results,
    check-extractions, ledger, scrub and paper.
  - CI runs check-refs, scrub, ledger and the self-tests.
    It does not build the PDF or check result files (the template's example
    result has no real commit, so check-results fails until you delete it).
- `AGENTS.md` and `GEMINI.md` are symlinks to this file.
  Keep it neutral to the agent.
